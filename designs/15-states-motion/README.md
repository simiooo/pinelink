## 现有契约与显示规则

核对来源：`infra/migrations/003_transfers_tasks.sql`、`005_devices_gc.sql`、`001_init.sql`；`backend/internal/service/devices.go`、`transfer.go`、`tasks.go`、`p2p.go`、`pull.go`、`file_lifecycle.go`；`web/src/i18n/status.ts`。

| 事实来源 | 展示 | 动作与边界 |
|---|---|---|
| device `ACTIVE` | 授权有效；在线状态另由连接证据决定 | 不能仅因 ACTIVE 显示在线；未知时等待连接，不虚构心跳阈值 |
| device `REVOKED` | 锁形标记、不可放置 | 阻止发送；服务端取消结果优先于旧的传输动画 |
| UI reachability | 在线实心点、连接中空心点、离线降低透明度 | 在线/离线是可达性，不是新增的服务端设备枚举 |
| `PENDING` | 发送方 Waiting；接收方 Receive request | 接受后才能进入连接；拒绝、取消、过期各有独立终态 |
| `ACCEPTED` | Connecting，随后依据实际任务进入活动态 | 接受不是完成，不先显示对勾 |
| task `QUEUED` | Queued；静止轨道 | 不播放传输活动段 |
| task `RUNNING` | 两个节点、一条曲线、一段蓝色活动段 | 发送从本机流向对方；接收反向流向本机 |
| task `PAUSED` | 静止轨道、暂停 sheet | Resume 对应现有暂停任务；关闭 sheet 不自动继续任务 |
| task / transfer `FAILED` | Couldn’t send files | Try again 创建新的尝试，不能把 FAILED 当作 PAUSED 恢复 |
| `REJECTED` | Request declined | 可选另一台设备，不自动重新请求同一接收方 |
| `CANCELLED` | Cancelled，随后恢复设备图 | 取消先确认；Keep transfer 保持原运行或暂停状态，不改变它 |
| transfer `EXPIRED` | Request expired | 文件仍可用时创建新请求；端侧倒计时只触发刷新，不覆盖新版本 |
| file `EXPIRED` / `DELETED` / 不可读 | File unavailable / Couldn’t read the file | 重新选择文件，不能重用失效引用 |
| `UPLOAD COMPLETED` + file `AVAILABLE` / version `SEALED` | Stored in cloud | 只说明云端已有副本，不说明接收方收到 |
| 校验成功的 P2P `COMPLETED`，或下载完成且有有效 delivery receipt | 发送方 Delivered；接收方 Received | 送达对勾放在真正接收文件的设备上；不依赖字节百分比推断 |
| task `DELETED` | 从默认历史视图移除 | 服务端确认后才淡出并重排，不等于删除云端文件 |
| HTTP 409 / 新版本事件 | 采用当前权威快照 | 中断旧过渡，不让迟到的暂停/失败回包覆盖已完成状态 |

`Cloud` 是存储能力标记，可与在线状态共存。`BROADCAST` 复用每个接收设备的状态，不把一个设备的成功当作全体成功。一个活动任务保持当前双节点视图，其他任务入口放入次级操作。

## 本地交互状态

`idle → dragging → target / blocked → staged → submitting → pending`。这些是界面状态，不新增后端枚举。

- 进入画布时仅显示一条 `Drop on a device` 提示。
- PC 普通节点半径 32px，命中范围扩展 24px 到 56px；离开时多留 8px 滞回区。以图标圆心计算，不把文件名当作命中区。
- 进入有效范围后，64px 节点长至 72px；112px 浅蓝接收圈、加号与 `Drop to send` 同时出现。不会因为缩放而改变命中半径。
- 无效位置使用中性灰、禁止或锁形标记与短原因。离线、撤销授权、本机、尚未连接等原因分别处理，不用蓝色暗示可放置。
- 拖拽期间冻结节点布局；相邻目标取最近圆心。移过图标、标签、子元素不闪烁；离开窗口、Esc、drop 或 dragend 都清理状态。
- 文件浮影代表系统拖拽影像，产品实现不与原生影像重复绘制。预览自动演示时才模拟该浮影。
- Drop 只暂存内容并打开 `Ready to send`。确认 Send 后才创建请求。无法读取时不能虚构文件名或数量；目录枚举未完成时显示读取状态并允许重新选择。
- 离线但具备异步保管能力时，可以显式选择 `Store in cloud`，必须二次确认；不把普通离线节点画成在线。
- 手机默认使用选择文件、系统分享和点击目标完成同一流程；支持拖拽的设备沿用同一命中语义，不依赖 hover 才可用。
- 一个拖拽手势只提交一次。提交期间禁用重复动作；发送确认、暂停、取消等按钮的最终反馈等待服务端结果。

## 动效参数

完整参数在 OpenPencil 的 Motion 页与 `motion.json` 中。进入/变化使用 `cubic-bezier(.16,1,.3,1)`；退出使用 `cubic-bezier(.4,0,1,1)`。

| 元素 | 进入 / 变化 | 退出 |
|---|---|---|
| 节点 | 200ms；透明度 0→1、缩放 .96→1、y 8→0；40ms 短错峰，累计不超过 120ms | 160ms；淡出、缩至 .96、y -4；退出后再重排 |
| 选中 | 180ms；64→96，背景上下文退至 .13 | 180ms 回到原位置与原尺寸 |
| Drop 目标 | 120ms；光圈、加号、72px 节点出现 | 100ms 清理光圈并恢复 |
| Drop 确认 | 140ms 结束系统影像，随后打开确认层 | Esc / 离开画布 100–120ms 清理，不发送 |
| 桌面浮层 | 180ms；y 8→0、.98→1、透明度 0→1 | 120ms；y 0→4、缩至 .985、淡出 |
| 手机 sheet | 240ms；y 24→0、淡入；背景同步 160ms | 180ms；y 0→24、淡出，随后恢复焦点 |
| 传输活动 | 1800ms 匀速循环；轨道 3px、单段蓝色 4px，约占路径 12% | 暂停/断线停止；不是完成百分比 |
| 送达 | 收到回执后 140ms 收束，180ms 连接线退出；对勾反馈约 1800ms | 恢复设备图，保留用户焦点 |
| 历史记录删除 | 服务端确认后 140ms 淡出 | 160ms 网格重排；拖拽过程中延后布局变化 |

不使用回弹、晃动、庆祝粒子、循环光圈或伪 3D。长等待不靠不断加速或假的进度条安抚。新状态到来时取消旧动画并从当前视觉位置继续，保留稳定节点标识；终态优先于迟到回包。

## 降低动态与可访问性

遵守 `prefers-reduced-motion`，并提供预览开关。降低动态时取消位移、缩放、错峰和循环；状态采用至多 120ms 的透明度变化，传输段保持静止。页面隐藏时暂停持续动画。

图标按钮具备可访问名称、tooltip 与 48px 触控区。键盘可选择文件并选择目标，Enter 确认、Esc 退出；关键对话框先聚焦安全的次要动作。焦点限制在产品弹层内，关闭后回到触发节点；不会每一帧或每次 hover 播报状态，只播报操作结果。图标、描边和短文本共同表达状态。

## 验证

可播放演示通过 `check-15-motion.cjs` 检查拖拽吸附、离线/本机拒绝、确认边界、接收方向、成功回执、暂停取消、重试、新旧弹层冲突、降低动态和手机宽度。结果写入 `motion-verification.json`。OpenPencil 另做字体、对比度、触控、坐标与重开渲染检查。
