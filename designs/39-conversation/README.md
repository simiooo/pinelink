# 设备对话与文本投递 · 设计草案

SIM-895，基于用户 2026-11-04 的反馈。`../39-pinelink-conversation.fig` 为独立 OpenPencil 原生文件，13 个画板展示混合文件/Markdown、普通及敏感文本输入、接收同意、内容类型选择、320px、桌面面板、旧客户端回退、等待重试、复制失败、键盘及敏感内容回退确认。设计数据为示例，不表示功能已交付。原生文件通过 OpenPencil core 保存、重开并导出，GUI 当前 RPC 超时；`frame-*.png` 为同一文件重新读取后渲染。

- 对话按明确设备和服务/身份隔离，按真实记录顺序呈现收发；文件与文本同流，状态基于确认事实，不因云暂存声称送达。
- 普通文字安全渲染 Markdown，保留原文用于复制；不执行 HTML，不自动打开链接或加载远程图片。复制由用户触发，仅成功后显示成功，失败时允许选择原文。
- 敏感由发送者明确标记，默认遮盖，用户主动显示或复制；不把遮盖描述为防截屏、自动删除或服务端看不到元数据的保证。通知与传输元数据不含正文。
- 文件与文本仍有单次接收同意；接收前不展示正文。失败、离线等待、过期、兼容性和账号/设备切换仍需在实现及验收中覆盖；新内容类型需显式协商和安全回退，不能向旧客户端悄然声称支持。

本设计增量取代 v28 的网格历史提案；v28 身份、授权及加密约束继续适用。尚未实施、测试或发布文本能力。



## 实施与兼容要求

- 内容清单使用经过认证的版本和 `FILE` / `TEXT` 类型；文本另含普通或敏感标记。正文 UTF-8 原样加密、摘要校验、按现有传输授权和真实回执完成，正文不进入服务端文件名或通知。仅解密后的本地会话可读取；本地保留方式必须明确，遮盖不等于设备失窃防护。
- 文本上限按 UTF-8 字节计，空文本不可发送；超限保留输入并明确提供文件方案。明确协商对端类型能力，未知客户端不得自动进入新协议。普通文本可由用户明确选择作为文件发送；敏感内容的文件回退必须先明确提示文件保存和展示方式，不能静默降级。
- 未接收前展示设备和通用内容类型，不展示正文；拒绝、过期、复制失败、等待、断线恢复、重复提交与账户/服务切换均不能制造已送达状态。只与对应设备关联记录，不能暴露其他设备或用户的完整历史。
- Markdown 不执行 HTML、脚本或外部图片；链接只允许明确安全协议并由用户主动操作。普通和敏感文本都复制原始内容，复制失败可选择；敏感内容默认隐藏且在界面离开或身份切换后重新隐藏。
