# 访客身份、一次性连接与注册衔接

状态：设计预览已部署，访客运行功能实施中。SIM-915 以无需账号真实收发文件为一个独立交付单元。

## 一次配置

- 首次在本机生成独立 Ed25519 / X25519 身份，按服务 profile 与客户端隔离；不会创建隐蔽邮箱账号，也不共享 dev-owner。默认保留在本地，服务端只保存访客设备、公钥、限权会话与必要传输记录。
- 首次申请网络权限发生在明确连接或发送动作；不要由 React effect 重放创建多个访客。已有访客凭本机 proof 自动续接短期会话，无需重复输入配置。服务端幂等、Web Locks / 单实例初始化与 Flutter 操作门控共同保证一致性，不能只依赖单个组件的 busy 状态。
- 建议会话租约 24 小时、活跃时凭密钥续期；连接码 10 分钟。它们都不是文件保留期限，后者继续服从资源生命周期。具体匿名资源预算由私有服务配置决定，界面只在真正达到限制时展示原因和下一步，不预置登录墙。
- 若浏览器不能持久保存，可显式使用仅本标签页有效的临时身份；不静默降级成共享网络身份。提醒只在这一故障时出现。

## 一次性连接

QR / 链接使用 128-bit 随机令牌，优先放 URL fragment，读取后清理地址；人工码用 8 个易区分符号。示例 K7M4 8F2Q 不是真实令牌。服务端存 HMAC、过期和版本；GET、预览、相机识别、链接扫描均不消耗。

加入方先证明自己的访客或账号设备密钥。候选请求与具体双方公钥绑定，邀请者确认时才在单个事务中 CAS 消耗邀请、生成有界 peer grant；多个候选抢同一码只能有一个获批。拒绝某个候选不得自动授权其他设备，不把同一 IP / Wi-Fi 当成信任。

配对不等于永久信任或自动接受后续文件。仅当邀请已经绑定具体文件版本、接收者密钥、大小与 manifest 摘要时，明确的 Receive 可以一次原子确认配对和本次内容。普通配对后的每次新内容仍需现有接收策略。

首轮 Web 实现使用两步确认：Connect 仅确认具体设备，Receive 再确认具体文件；不会用没有绑定内容的连接请求提前授权收文件。新增独立配对请求与等待确认画面。仅标签页身份仍是后续提案；当前存储不可用时显示简短错误与重试，不以内存副本伪造持久保存和送达回执。

## 服务端权限

- 主体区分 account / guest / native-local，访客 owner 由服务端分配。继续验证设备签名，不通过关闭 ACCOUNT_REQUIRED / DEVICE_AUTH_REQUIRED、放开任意 owner 或临时开发密钥实现匿名。
- Web 的 guest Cookie 槽与现有 React / Flutter account Cookie 槽分开。每个请求固定主体种类、设备和 scope；账号过期不能静默改用访客去执行原账号操作。原生会话继续用独立 session header，不占用 staging Basic Authorization。
- 现有 account_sessions FK 与账号事务锁不能直接承载访客 UUID。需要独立 guest leases，并扩展授权事务和长连接监视到带类型主体；账号/访客各按一致顺序取得有效身份和租约锁，撤销/到期与 durable commit 原子排序。
- guest 会话只可访问本机资源及明确获批的 peer / transfer。跨访客、访客与账号配对均需要双端证明与具体授权；不开放匿名设备全局列表，不以知道文件 ID 代替访问权。
- 防滥用使用服务端资源预算、预留和原子计数、受信代理 IP 粗限流与并发上限。IP 不充当身份，换公钥也不能绕过服务整体预算。不能先接收任意大小的云资源再检查额度。

## 数据与进度

复用现有加密分块、receiving ledger、verified receipt 和 R2 资源引用机制。接收者密钥与目标确定后可以先暂存，仍不要求对方先接受；拒收/过期按既有引用、原子 GC 和资源删除规则处理。暂存完成不等于送达。

主图只保留两个设备和一条蓝灰曲线。蓝色由真实接收确认推进；云暂存走独立 cloud intent 节点，不能把上行 100% 冒充接收完成。1.8s 低干扰流光仅覆盖已确认蓝段；暂停、后台和 reduced-motion 停止装饰循环，不修改真实进度。数字、路线与操作进详情浮层。

暂停确认必须与服务端同一任务事务返回的最终接收字节数一起提交到本地，不能先以旧轮询的边界显示已暂停、随后再补进度。控制版本与进度版本共同过滤迟到响应；恢复回执不得覆盖更晚的接收确认，终态不能被旧控制回执重新激活。

本单元已实现并在双浏览器验证 Web 访客选择、加密、发送、接收、校验、保存闭环；实际运行环境验收另见工程记录。CLI 原生离线 LAN 继续独立工作；Web 不把“无需账号”说成“不依赖信令或浏览器权限”。

## 注册后的连续性

现有账号必须先由 Google / 密码确定，再选择其永久设备 profile。访客在途任务始终固定原密钥、账本、路由 epoch 和授权；登录不能因为替换全局 IDENTITY、cookie 或 runtime 而取消它。

账号运行时与访客在途运行时并行隔离，在途完成或用户明确取消后再释放旧会话。访客本地记录与私钥保留，允许在本机查看，不能直接改 owner_id、合并数据库或重用另一个账号的密钥。

在途时通过独立窗口进入现有登录流程，当前传输页保留。跨窗口账号广播不能刷新或关闭仍在传输的访客运行时。若浏览器无法另开窗口，先持久化已确认断点再跳转，返回后恢复；不承诺页面关闭后浏览器仍持续后台执行。

传输结束后，显式进入账号页面时核对账号、设备和会话对应的本地运行时。若原窗口仍保留旧的只读身份，则通过这次导航重新初始化账号页面；不在传输中切换全局主体，也不把旧只读运行时当成已登录账号。匿名本机文件仍使用独立入口和原来的密钥。

跨设备导入访客云资源或延长保管需要新鲜的账号证明和原访客设备证明、必要的密钥信封重包，以及带版本/配额检查的原子引用迁移。若该能力尚未就绪，登录只继续新账号能力，不声称旧访客云资源已自动同步。到期、撤销或来源资源变化时保持本地副本，明确失败并允许重试。

## 必须通过的验收

两独立浏览器完全不建账号，扫码/人工码只用一次，接收真实文件并核对 SHA-256 和回执；同时覆盖重复 effect/双击、两个 tab 续租、两设备竞争同一码、拒绝与迟到请求、过期/重放、断线恢复、已确认进度不回退、注册时在途任务继续、资源和账号隔离。所有检查在 Fedora，实际 staging 部署及相关路径冒烟完成后才移交工程验收。
