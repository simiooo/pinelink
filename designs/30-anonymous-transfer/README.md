# v30 · 先使用，再注册

SIM-915 设计提案；**尚未启用匿名运行服务**。继承 v20 节点图、v27 账号和 v29 动效。共享 OpenPencil 应用仍在最小英文文档上报告 CanvasKit 内存错误；本稿由独立 OpenPencil core 保存、回读并导出 PNG，不能将它写成 GUI 重开验收通过。

## 使用流程

1. 打开即进入访客主图。客户端一次生成本地访客身份，不要求邮箱、密码、设备昵称或服务器配置；“登录”保留为次要入口。
2. 扫码或输入连接码建立这次连接。对方明确确认；已有文件时，一次“接收”同时确认绑定密钥的连接与该文件。
3. 无需账号完成加密直连或即时中继。进度沿用真实接收账本的蓝灰曲线，流光表示活动，暂停时停止。
4. 收到并校验后可以继续发送。用户主动选择长期保管等账号能力时再显示登录入口，可退出引导继续匿名使用。

“一次性”指初始化与配对凭证，不是只允许免费试传一次。临时会话可以凭本机密钥续接，本地文件与历史不随连接码到期删除。连接码到期只重新生成连接凭证；清除浏览器数据后无法凭 IP 或相同设备名恢复访客私钥。

## 交付门槛

本次新流程先设计、改稿和验收。实施必须包含真实 Web 文件数据面所需的最小闭环，不能仅增加“访客”按钮或签发临时 token。复用 SIM-859 与 SIM-895 的协议和需求，避免另建一套不兼容的传输账本；其完整离线 outbox、文本和其他未采用流程仍分别追踪。

工程验收包含两独立浏览器零账号配对、真实文件 hash/回执、接收拒绝/过期、并发使用同一码、刷新/断线续接、注册不打断在途传输、身份和配额隔离，最后实际部署 staging。设计预览发布不计匿名功能交付完成。

## 调研依据

[PairDrop 官方说明](https://github.com/schlagmichdoch/PairDrop/blob/master/README.md)使用临时房间或配对连接不同网络的设备；本提案借鉴其免账号入口和配对方式，但采用绑定具体密钥与接收授权的一次性邀请，不开放任意访客可枚举的公共设备目录。[官方 FAQ](https://github.com/schlagmichdoch/PairDrop/blob/master/docs/faq.md)也说明，浏览器端发现或传输所需的在线基础设施，与“不需要账号”属于不同边界；原生离线 LAN 能力继续保留，不据此承诺 Web 无条件脱离信令服务。

二维码编码的是保留示例域名，仅用于设计，不包含真实邀请、配置凭据或私钥。
