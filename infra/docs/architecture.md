# Pinelink 架构基线

## 1. 目标与边界

Pinelink 的目标是让文件完整、可信、可理解地到达正确的人。直连、中继、暂存、持久化和节点界面共同服务这个目标。

网络路径切换对用户无感，但数据保管策略不暗变。会话创建时声明：直连不留服务端副本；经过中继时可生成免费保留 24 小时的加密临时副本。持久化必须由用户操作或预先声明的策略触发。

## 2. 三个正交维度

- 交付意图：`ONLINE`、`ASYNC`、`BROADCAST`。
- 网络路径：`DIRECT`、`RELAY`。
- 副本策略：`NONE`、`TEMP_24H`、`PERSISTENT`。

允许会话内 `DIRECT <-> RELAY` 迁移，保持同一 `transfer_id` 和连续真实进度。禁止在线失败后静默转入广播或持久化。

`AVAILABLE`、`DELIVERED`、`PERSISTED`、`READ` 是不同事实。首次完整交付回执不被后续下载覆盖。

## 3. 网络与应用中继

- 在线跨平台数据面使用 WebRTC，Go 侧采用 Pion；离线原生直连增加固定设备公钥的TLS 1.3 / HTTPS通道，共用应用层加密与接收回执语义。
- ICE 覆盖局域网、VPN、IPv4/IPv6、STUN 反射地址和标准 TURN；私网候选优先，公网直连其次，应用中继兜底。
- 不手写 NAT 穿透、拥塞控制、重传、DTLS 或 SCTP。
- 应用中继分别终止发送端和接收端的 WebRTC 连接，从而获得可暂存的密文分块。
- 文件另有发送端到接收端的应用层端到端加密；中继和对象存储不持有明文或内容密钥。
- 路径迁移使用共同的分块清单和恢复账本，不重新实现传输层协议。

## 4. 暂存、保留与重复拉取

中继转发与暂存并行，分别确认交付和暂存状态。暂存状态为 `NOT_REQUIRED`、`SPOOLING`、`PARTIAL`、`SEALED`、`EXPIRED`、`FAILED`。只有 `SEALED` 副本可离线拉取或提升为持久化。

免费完整临时副本自封存起保留 24 小时，未完成副本在最后活动 24 小时后清理。拉取和重试不续期。

`TEMP_24H -> PROMOTING -> PERSISTED` 需要授权、配额预留、持久化保留锁和完整清单校验。对象引用与清理由同一权威模型协调。

`FileVersion` 表示不可变内容；`DeliveryReceipt` 表示每个接收者/设备的首次完整交付；`PullSession` 表示每次下载。持久化模式允许同一终端反复拉取，每次重新授权，支持分块和 Range 续传。

## 5. 内容缓存与秒传

首版实现限定安全域和加密域内的整文件秒传，以及上传会话内的分块续传。不做跨用户全局秒传或跨文件分块去重。

客户端使用 SHA-256 计算分块和文件内容根，以域密钥计算 HMAC 去重标识。服务端只接受 `(dedup_scope_id, encryption_domain_id, hash_version, dedup_key)` 匹配，不开放全局明文哈希存在性查询。

命中后仍需授权，并由客户端解密 manifest 验证内容根，再提交引用。哈希不是权限，缓存不替代交付确认。

`FileEntry` 是用户可见的逻辑文件，`FileVersion` 是不可变加密版本。多个逻辑文件可引用同一物理版本；配额按物理占用计算。最后引用消失后进入宽限期和幂等垃圾回收。

## 6. 状态与事件

在线服务以PostgreSQL为权威状态。业务状态与 Outbox 在同一事务提交，Go Worker 发布到 NATS JetStream。消费者按 `event_id` 幂等，按聚合版本防止状态倒退。无中心服务的本地传输以接收设备的持久账本为权威；分块同步与原子checkpoint后才确认进度，完整校验及本地文件提交后签回执。配对、授权、进度、回执和本地历史均不等待云端；详见[离线局域网契约](offline-local-delivery.md)。本地ID带独立控制域，重新联网不把本地送达伪装成中心服务签发的回执。

NATS Core 用于临时实时内部消息，JetStream 用于可靠领域事件和后台任务。文件字节、高频逐块进度不进入 NATS。客户端断线通过事件游标补拉，并以权威快照校准。

默认表现层只消费稳定任务投影；`PATH_CHANGED` 进入诊断，不触发不同传输叙事。动画时间不作为真实传输时间约束。

2026-11-01 的进度交互修订见 [传输进度与交互契约](transfer-progress.md)。主图以蓝/灰弧长表达已确认/剩余字节，数字和操作放进详情 modal / bottom sheet。独立进度序号、采样时间、双方权限及原子投影已由SIM-844实施；v20界面迁移仍需后续单元。

历史保留、文件可复用性与云节点恢复的设计修订见 [历史可用性与云端恢复契约](history-availability.md)。独立副本读取授权决定能否在传输完成后再次恢复；可复用性、保留策略和商业权益分别校验，不用过去的送达记录替代当前访问权。

中继先上传、接收同意后下行及引用安全回收的修订见 [中继预上传与原子生命周期](relay-preupload.md)。拒绝/到期同事务撤权并释放本次投递引用，通过 Outbox 触发可重试 GC；引用、保留锁和有效 I/O 租约归零后，按不可重用的存储代际删除。云生命周期已由SIM-847（维护者内部验收记录）实施并部署staging，过期策略保持不变。

直连与中继/云策略的双路径修订见[统一送达与独立云副本契约](direct-relay-delivery.md)。DIRECT与在线RELAY使用同一接收确认账本，路径切换不重置进度；云暂存确认独立。只有实际云端阶段使用Cloud节点，送达成功和云封存失败可同时成立。P2P进度与确认基础已由SIM-844（维护者内部验收记录）实施并部署staging；云生命周期见SIM-847，v20界面仍待后续单元。

## 7. 技术栈与项目边界

- `backend`：Go、Kratos/gRPC/HTTP、Pion、PostgreSQL/pgx、NATS、S3 兼容对象存储。
- `cli`：Go CLI，复用版本化 API，实现哈希、上传预检、断点上传、秒传和重复拉取。
- `infra`：开发及集成测试 Docker Compose、数据库迁移、NATS/SeaweedFS 初始化和架构基线。

所有开发中间件运行在构建机 Docker Compose，并显式暴露端口。首版使用 PostgreSQL、NATS JetStream、SeaweedFS；不把 Redis 或 Kafka 作为默认依赖。

## 9. 核心验收

- 相同安全域和加密域重复上传不增加物理对象，跨域不泄露内容存在性。
- 重复分块、重复事件和重复拉取不会破坏状态。
- 暂存不完整不得发布 `AVAILABLE` 或 `PERSISTED`。
- 同一终端多次完整下载产生多个 `PullSession`，首次交付回执不倒退。
- 免费副本到期不可拉取，提升过程中的对象不会被清理器误删。
- 中继、NATS、数据库和对象存储中不存在明文文件及可用内容密钥。
