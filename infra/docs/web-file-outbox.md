# Web文件数据面与离线意图队列提案

SIM-859，2026-11-02。本文和`designs/23-pwa-offline`是待验收提案，没有实施新增交互、文件数据面、迁移或通用命令回执。依赖SIM-847/850/852/854/857，服务profile切换边界沿用SIM-856。

## 交互与状态

| 本机状态 | 可见状态 | 可进入下一步的证据 |
| --- | --- | --- |
| Staging | 保存中，发送不可用 | 文件或分块已完成持久提交、manifest完整 |
| Ready | 文件图标上的本机保存标记 | 尚未创建发送请求；用户明确点击发送 |
| Queued | 本机时钟徽标，详情显示等待连接 | 用户意图已提交本地事务；没有可用授权路线 |
| Sending | 两节点、蓝灰真实确认量和流光 | 真实传输活动、有效授权及接收账本 |
| Unknown | 等待核对，不报服务器已执行 | 操作可能已提交，但响应丢失；先查稳定回执 |
| Cancel pending | 取消待确认，保留已确认蓝色前缀并停流光 | 已停止本机发送，但远端结果尚未确认 |
| Conflict/Expired | 简短原因与下一步 | 需要最新状态、权限或用户重新决定 |
| Local failure | 空间不足等短错误 | 未完成本地提交，不显示已保存/已排队 |
| Delivered | 已送达 | 接收端完整校验、文件提交及有效回执 |

中心不可达不阻止已认证可用的LAN路线。“可用”来自当前授权/握手/传输连通性，不以配对名单或navigator.onLine猜测。纯浏览器重开后如需重新协商，复用v21的连接码/比较码方向；v21相关交互也须验收。PWA不会凭安装获得UDP发现、无条件本地HTTPS证书信任或无限后台执行能力。

没有路线时，文件先持久保存在本机，用户通过“连接后发送”创建待执行意图。路线选择在首次网络副作用前原子绑定控制域；一旦发送结果未知，不能另走另一控制域自动再建一笔。无中心新建的本地传输由接收设备授权/回执，联网后复制历史事实，不伪装成服务器签发的云端送达状态。

## 本地文件与事务

- 每个服务/账户/设备/信任代次隔离身份、文件、草稿、意图及同步游标；Service Worker只处理活动profile和对应代次。
- 文件使用已验收协议的应用层内容加密和元数据封装；浏览器实现先以Go兼容向量验证，不降级到明文。初期候选为Dexie/IndexedDB加密分块，密钥由本地不可导出密钥保护。分块大小、并行度和内存均有界，不将大文件一次读入内存。
- 加密在持久事务外进行，完成分块逐步写入Staging。最终事务验证完整分块/manifest后发布Ready；创建发送时，同事务增加本机引用和写入意图。UI不在File对象刚选中或写入尚未完成时显示已保存。
- 如采用OPFS，外部文件I/O不能假装与IndexedDB同事务。采用不可变代次、完成文件提交后再发布指针、引用/租约及可续做GC；后台读取能力须逐浏览器验证，不能默认Service Worker可使用Dedicated Worker专属文件API。
- quota estimate只是提示，以真实提交结果处理QuotaExceededError。失败保留可重试的草稿信息，不创建虚假的Ready；清理只处理本profile拥有的零引用孤儿代次，不触碰用户其他文件或云端独立副本。
- 本地意图时间与服务器投递/暂存到期时间分开；未创建云请求的本机草稿不因服务器24h投递策略提前过期。已有服务器请求到期后停止该请求，保留确实在本机的文件，由用户决定新发送。

## 命令与稳定回执

现有`service.ControlTask`在任务已经处于目标状态时直接返回，否则按expected_version控制；这提供目标状态幂等性，并不识别某个独立操作。`replication_operations`目前用于配对名单操作，也不是文件/任务通用回执。客户端不能用“现在恰好是暂停”推断某次离线暂停操作已成功。

拟为可离线重试的业务命令建立稳定回执封装：

1. 本地意图保留intent_id、不可变语义payload hash、聚合及预期版本、接收者信任根、本地顺序、控制域/服务代次。首次网络执行前生成并持久绑定operation_id与服务器epoch；每次HTTP重试重新生成短期签名，不缓存旧签名请求、临时下载URL或管理凭据。
2. 服务端按认证主体/设备/operation_id唯一定位，在同一数据库事务中校验payload hash、执行状态/CAS、写业务outbox和稳定操作结果。重复内容返回原结果，不再次扣配额、创建投递或增加引用；同ID不同内容拒绝。
3. 回执保存稳定ID、结果版本和成功/确定拒绝，不保存可被反复使用的过期临时URL。客户端响应丢失时查询回执，更新投影仍遵守版本屏障，旧回执不能覆盖更新的状态。
4. 冲突、过期、撤权、信任变更停为需要处理，不自动改expected_version或悄悄生成新操作ID重试。独立聚合公平推进；一个失败意图不阻塞所有文件。
5. 尚未认领/发出的意图可在本地事务中取消并释放该意图引用，保留独立的本机文件/草稿引用。已发出或结果未知时保存取消意图，先核对原操作回执再执行合法取消；原传输已校验完成时以真实送达结果为准，不伪造取消。
6. 回执保留/墓碑和操作epoch必须防止清理后重放。超出可验证重试范围或服务恢复导致epoch变化时进入重新核对，不能把旧操作当新操作再次执行。云端现有不可变对象代次、原子引用和迟到PUT回收继续适用。

## 文件传输与界面落地

Web应直接完成文件加密、授权后的WebRTC/中继传输、云暂存与恢复，替换当前仅生成CLI命令的发送准备页。后台能力按平台增强，前台/重开后的自动续做必须可靠；不能以CLI成功代替浏览器数据面验收。

直连/在线中继蓝灰边界来自同一接收账本；云上行与送达独立。Queued没有传输流光；暂停/结果未知保留已确认前缀并停动画；实际传输只在已确认蓝色段内播放v20流光。100%上行不等于已送达。

离线记录沿用设备名标题和文件图标网格，只在图标上用本机/时钟/云/异常微标记。待同步本机条目进入All，不将其伪装成云端Reusable/One-time/Expired事实。PC浮层、移动全屏，密集文字局部左对齐；图标需可访问名称、tooltip和键盘焦点。
