# 三方增量复制与自动补同步

SIM-850按照用户指定顺序先交付此协议/原生单元，再接Web、Flutter本地持久化。此文描述实现，不把端到端工程验收等同于整个产品已完成。

## 权威与身份

原生接收账本、发送意图和服务器云对象事实保持独立。客户端历史事件不会写服务器的传输状态、grant、配额或引用计数。复制只更新本地历史投影，接收回执必须由实际接收设备签名；服务器事实由独立服务器Ed25519密钥签名。

每个本地profile保留原设备私钥。云绑定使用独立的cloud owner/device参数，不重置离线身份。服务端验证该身份当前注册的公钥，再绑定公钥指纹root；不把相同owner字符串当作账户内所有设备的读取权。首次注册也必须证明私钥持有。未来真实账户成员管理需要独立认证层。

云端互相分享历史需要双方分别提交已配对公钥名单；单向声明无权读取对方记录。名单修改有操作ID和乐观版本，旧的允许操作不能重放撤销新撤权。撤权在服务器收到并提交后阻止后续共享读取；离线的一端不能即时通知服务器，已经获得的文件和历史也不能远程收回。本地立即停止应用来自已撤销设备的新投影。

## 数据与确认

业务事件的文件名、私密元数据、完整接收回执使用age加密给本人和对应的已配对设备，服务器只存密文及路由头。加密后的字节和签名先持久化，重试不重新随机加密。签名采用版本化域分隔及递归排序的JSON对象键，整数保留精度；共享Go协议包提供测试向量。服务器旧业务事件通过明确字段白名单投影，不重放文件名或密钥信封。

源游标为root + SQLite stream + sequence；目标feed有独立epoch与提交顺序安全的投递序号。客户端只有验证服务端/对端签名确认后才推进上传位置；只有inbox去重、历史投影与消费位置同一SQLite事务提交后才认为拉取完成。相同事件ID不同内容拒绝，旧版本不能覆盖新事实。逐块进度仍只写checkpoint。

PostgreSQL业务outbox使用待投影工作标记扫描已提交记录，不以MAX(sequence)跳过可能晚提交的事务。复制写入先锁专用metadata行，再分配feed计数；计数与投递同事务。授权后补发既有共享事件使用有界backfill任务，重新授权具有新投递世代。

## 初始化与恢复

首次连接使用带固定上界和分页位置的快照，再从该上界消费增量。快照未取完时保存其上界与分页key，重启继续；远端epoch改变或游标超前时重新校准，不删除本人的运行中账本和过去已验证事实。

原生`lan serve`默认运行同步worker；无接收界面时可用`lan sync run`。worker持有本机独占lease，目标状态、重试次数、下一次尝试时间和错误均落SQLite，网络恢复后自动重试；单轮目标和批次数量有界。对端地址失效时，可在mDNS候选中寻找原指纹，再通过原公钥固定验证后只更新地址，不自动信任陌生设备。

发送意图在尝试联系对端前落库。普通发送开启自动恢复；`--offer-only`保留显式稍后发送语义。对端恢复后补发尚未建立的请求，接收同意后恢复密文发送；暂停不擅自继续，取消/拒绝/过期不复活。接收端已有签名完成事实可补齐发送端的本地回执。同步失败不回退送达，送达也不等于云封存成功。

本机控制用回环地址，监听器广告地址只供对端连接；网卡暂时消失时仍能在本机接受/拒绝已有请求。

## 运维入口

`PINELINK_HISTORY_SIGNING_SEED`是32字节Base64服务器签名种子，staging部署脚本首次生成并保存到被忽略的env文件。公钥通过带nonce的签名info响应公开；绑定时固定公钥，HTTP场景必须显式提供。客户端用签名服务器时间计算请求签名偏移，不修改系统时钟。

```sh
pinelink lan sync bind --server https://server --server-key '<public key>' --cloud-owner account --cloud-device device
pinelink lan sync status
pinelink lan sync once
pinelink lan sync run
pinelink lan sync history
pinelink lan sync disable
```

`--configure-only`可在云端不可用时先保存配置。常规重启保持设备和epoch；被撤销的云端设备不会由后台反复注册，重新绑定需要显式操作。私钥、邀请、密钥信封和签名种子不得进入日志或交付记录。
